## 1. 交付结论（请甲方据此验收口径）

**结论：可以按「第 1 期里程碑 + MHI 协议试点样板」交付联调与阶段验收；不宜按「全载荷、全 SPO sheet 终验」口径验收。**

| 维度 | 是否达标 | 说明 |
|------|----------|------|
| SRS 规定的接口职责（收载荷打包数据 → 处理 → 存/日志 → 转发仿真侧） | **是** | 编排链路已打通 |
| 统一 JSON 外壳 `code/msg/data` | **是** | 对齐图扑接口模板 |
| 按 SPO.xlsx **完整**解全部工程遥测/科学帧 sheet | **否** | 当前仅 **MHI 两张 sheet 试点** |
| 按 接口.docx 对全部入站做 RS422 帧同步 | **部分** | 已实现表 43 校验/组包能力；科学帧默认不强制套用 |
| 真实 TCP / 真实库持久化 | **否（本期不做）** | 分期计划明确：NB-002/003/004 首版为内存 Port + mock |

因此：

- **可交付**：接口形态、主模块流水线、MHI 科学帧头/工程参数试点解帧、自动化测试与 curl 用例。
- **后续迭代**：其余载荷字典导入、位域/转换公式全集、真实链路与库表。

## 3. 开发逻辑

### 3.1 业务链路（与 SRS / 分期一致）

```
载荷单机
   │  HTTP POST /api/open/wb/001/payload-data
   ▼
WbApiController（入站校验）
   ▼
MainModuleOrchestrator.ingestPayloadData
   ├─① PayloadFrameDecodeService.decode     ← SPO 解帧 / 可选 RS422 校验
   ├─② InstructionProcessService.process    ← JK-NB-001
   ├─③ StoreWritePort.store                 ← JK-NB-004（内存）
   ├─④ OutboundClient.sendToSimPlatform     ← JK-WB-002（mock 出站）
   ├─⑤ TcpCommunicationPort.send            ← JK-NB-002（骨架）
   └─⑥ LogWritePort.write                   ← JK-NB-003（内存）
```

### 3.2 入站两种模式

| 模式 | 触发条件 | 行为 |
|------|----------|------|
| **SPO 试点解帧（推荐）** | 同时提供 `frameType` + `rawHex`（或兼容字段 `rawDigest`） | 按 `MhiPilotDictionary` 字段表按字节/位抽取，应用 FHEX / FUDEC1 / FST 等公式，返回 `spoFields` |
| **SRS 示例兼容** | 未提供 `frameType`，传 `magX/Y/Z` 等 | 仅跑通流水线；计算 `magTotal` 等示例量，**不代表正式协议** |

支持的试点 `frameType`：

| frameType | 对应 SPO sheet | 解出的主要星上标识 |
|-----------|----------------|-------------------|
| `MHI_SCI_20000` | `41.科学数据帧头_20000_磁场与速度场成像仪科学数据1` | SCI200001～SCI200005（同步码、包标识、包序、包长、系统时间码） |
| `MHI_ENG_13001` | `32.工程遥测参数_13001_磁场与速度场成像仪工程参数` | MHIENG003～006、008、009（试点子集，字节对齐字段） |

可选：`validateRs422=true` 时先按 接口.docx 表 43 校验包头与累加和，再解 SPO。**科学帧头一般不开启**（帧结构不同于 RS422 指令包）。

### 3.3 核心代码落点

| 层级 | 类 | 职责 |
|------|-----|------|
| `common` | `SpoFieldDef` / `SpoFrameParser` / `MhiPilotDictionary` | SPO 字段模型与解帧 |
| `common` | `Rs422FrameCodec` | 接口.docx 表 43 组包/校验 |
| `common` | `Wb001PayloadDataRequest` / `Wb002ParsedPayloadData` | 入站/出站 DTO |
| `open` | `PayloadFrameDecodeService` | WB-001 解帧入口 |
| `open` | `MainModuleOrchestrator` | 主模块编排 |
| `open` | `WbApiController` | HTTP 暴露 |
| `boot-open` | `OpenApplication` + `/test.html` | 进程启动与联调页 |

## 4. 如何测试

### 4.1 环境准备

```bash
# 编译并跑自动化测试
./mvnw -pl common,open,boot-open -am test

# 启动外联服务（需先停掉旧进程再启，否则仍是旧 class）
./scripts/dev-start-open.sh
# 或
./mvnw -pl boot-open -am spring-boot:run
```

- 服务地址：`http://localhost:8081`
- 联调页：`http://localhost:8081/test.html`
- 设计说明与 curl：`docs/api_design.md` §4

### 4.2 手工验收（curl）

**用例 A — MHI 科学帧头试点（主验收）**

```bash
curl -s -X POST 'http://localhost:8081/api/open/wb/001/payload-data' \
  -H 'Content-Type: application/json' \
  -d '{
    "payloadId": "PL-MHI",
    "frameType": "MHI_SCI_20000",
    "rawHex": "EB90 2000 0001 000A 0000000186A0"
  }' | jq .
```

期望：`code=0`；`data.spoFields.SCI200001="0xEB90"`；`SCI200004=10`；`SCI200005=100000`；`satTime=100000`。

**用例 B — MHI 工程参数试点**

```bash
curl -s -X POST 'http://localhost:8081/api/open/wb/001/payload-data' \
  -H 'Content-Type: application/json' \
  -d '{
    "payloadId": "PL-MHI",
    "frameType": "MHI_ENG_13001",
    "rawHex": "000000000000000000000000EB901301000200080000000000000507"
  }' | jq .
```

期望：`code=0`；`spoFields` 含 `MHIENG003=0xEB90`、`MHIENG008=5`、`MHIENG009=7` 等。

**用例 C — 参数校验失败**

```bash
curl -s -X POST 'http://localhost:8081/api/open/wb/001/payload-data' \
  -H 'Content-Type: application/json' \
  -d '{}' | jq .
```

期望：HTTP 400 / `code=400`（缺少 `payloadId`）。

**辅助查询**

```bash
curl -s 'http://localhost:8081/api/open/wb/005/dashboard' | jq .
curl -s 'http://localhost:8081/api/open/debug/state?limit=20' | jq .
```
