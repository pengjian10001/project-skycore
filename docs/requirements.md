## 1. 系统目标

太阳极轨天文台有效载荷集成测试**仿真数据管理软件**（缩略名：仿真数据管理软件）面向载荷集成测试场景，在 Windows 环境运行，完成：

1. 接收、解析载荷下发指令，并与仿真平台双向转发指令/仿真数据  
2. 完整存储测试相关数据（科学数据、遥测、工程参数、指令与日志）  
3. 向外输出仿真运算生成的数据  
4. 提供操作员 Web 界面：实时监控、任务与数据管理、日志与系统管理  
5. 为大屏看板等查询终端提供数据服务接口  

## 2. 参与者与外部系统

| 参与者 / 系统 | 交互方式 | 说明 |
|---------------|----------|------|
| 载荷单机 | 外部接口 WB-001 / WB-004；数据流图中的 TCP | 上送打包载荷数据；接收转发的仿真指令/打包仿真数据 |
| 仿真平台（功能仿真） | 外部接口 WB-002 / WB-003；TCP | 接收解析后载荷数据；下发仿真指令 |
| 大屏看板 / 图扑类前端 | 外部接口 WB-005（HTTP/WebSocket） | 视图与监控数据展示 |
| 测试操作员 / 系统管理员 | 内部 Web 页面 | 登录后使用监控、任务、统计、查询、存储、日志、系统管理 |
| SPO / 载荷协议字典 | 离线配置（`SPO.xlsx`） | 指令、遥测、科学帧字段与判读规则的权威定义 |

## 3. 核心数据流（摘要）

1. TCP/外联通道接收载荷单机打包指令 → 指令信息处理解析 → 主模块调度 → 存储与日志  
2. 仿真数据经指令信息处理打包 → TCP 反馈载荷单机；解析后的载荷指令反馈功能仿真  
3. 主模块统一统计分析与入库  
4. Web 界面查询与管理已入库数据及运行状态  
5. 大屏看板通过数据服务接口拉取/订阅视图数据

## 5. 接口需求摘要

### 5.1 外部接口 `JK-WB`

| 标识 | 名称 | 方向（相对本软件） |
|------|------|--------------------|
| WB-001 | 载荷单机载荷数据接口 | 入：接收打包数据 |
| WB-002 | 仿真平台载荷数据接口 | 出：解析后发给仿真平台 |
| WB-003 | 仿真平台仿真指令接口 | 入：接收仿真指令 |
| WB-004 | 载荷单机仿真指令接口 | 出：转发指令至载荷单机 |
| WB-005 | 视图展示接口 | 出：大屏看板数据/视图 |

SRS 接口表写明协议为 **HTTP API**；数据流图同时强调 **TCP**。实现上外联部署单元需同时覆盖 TCP 链路与 HTTP/API 适配（详见需求分析缺口）。

### 5.2 内部接口 `JK-NB`（进程内组件边界）

| 标识 | 名称 | 用途 |
|------|------|------|
| NB-001 | 指令信息处理接口 | TCP → 解析/打包 |
| NB-002 | TCP 通信接口 | 打包/解析结果回 TCP |
| NB-003 | 日志接口 | 操作与运行日志落库 |
| NB-004 | 存储接口 | 指令与仿真数据落库 |
| NB-005 | 数据实时监控接口 | 汇总指令/数据/日志/存储供监控展示 |

## 6. 数据与字典

- 业务数据类型：科学数据、遥测数据、工程参数、指令、日志、任务元数据、存储告警。  
- **字段权威源**：`docs/original/SPO.xlsx`（指令列表/格式、工程遥测参数、科学数据帧头与包格式、判读与约束规则等，约 129 个 sheet）。  
- SRS 中接口数据元素表多为示例字段；落地解析必须以 SPO 与 `接口.docx`（MHI/RS422 等）为准。

## 7. 非功能性要点

| 类别 | 标识 | 要点 |
|------|------|------|
| 性能-存储/检索 | `XN-ZHSJ-SJCC` 等 | 指令数据检索响应时间 ≤ 100 ms；导出至少 txt/CSV |
| 性能-TCP/通信 | `XN-ZHSJ-JKTX` | 能接收载荷指令并发送数字量遥测、工程参数、科学数据等 |
| 运维-日志 | `XN-YW-RZ` | 运行状态、指令统计、存储信息分类记录 |
| 安全/保密 | `FGN-AQ` / `FGN-BM` | 按 SRS 安全与保密要求执行 |
| 设计约束 | `FGN-SJ` | 支持 Windows；界面一致、易用、简洁；快速部署 |
| 运行环境 | `FGN-HJ-*` | 硬件/软件环境见 SRS 第 5 章 |

## 9. 模块化部署约束（项目决策）

与外部系统交互的接口服务、与内部页面交互的管控服务，拆为**不同模块并独立部署**（目录名不加 `module-` 前缀）：

- `boot-open`（业务 jar：`open`）：外联 + 后台处理流水线（第 1 期）  
- `boot-console`（业务 jar：各 `console-*`）：操作员页面后端，按功能分次开发（第 2～8 期）  

分期定位、部署与测试见 [phased_delivery.md](phased_delivery.md)。  
目录与依赖约定见 [多模块Maven项目目录结构规范.md](多模块Maven项目目录结构规范.md)。
